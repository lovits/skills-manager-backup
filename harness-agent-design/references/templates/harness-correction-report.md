# Harness Correction Report

## 1. Current Design Read

- current operating shape
- what has already been decided
- what still appears sound

## 2. Failure Signals

- what symptom triggered the redesign
- what failure mode or contradiction is visible
- what invariant appears broken

## 3. Wrong-Turn Diagnosis

- likely wrong family read, wrong branch choice, or wrong subsystem posture
- why that choice no longer fits the actual pressure
- smaller alternative that fits better

## 4. Minimal Corrective Actions

- what to keep
- what to remove, downgrade, or defer
- what to replace or add
- what branch must be reopened to validate the correction

## 5. Corrected Runtime Direction

- corrected family read
- corrected branch order
- corrected runtime story in short form

## 6. Risks After Correction

- what remains unresolved
- what should be tested next
- what larger redesign is still intentionally rejected
